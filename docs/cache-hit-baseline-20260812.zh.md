# dsh 前缀缓存命中率基线（2026-08-12）

[English](cache-hit-baseline-20260812.md) | 中文

> **目的**：第一批天枢能力融合"评估分析"的基线收集——Wave 4（前缀缓存固化）前后对比的基准。测量脚本：`examples/headless-agent/baseline-probe.mts`（真实模型 + 真实会话形态，可复现）。

## 测量方法

- **载体**：examples/headless-agent 的 codingHarness（真实 LlmDeepSeek 适配器 + 真实 bash/todo 工具）
- **模型**：deepseek-official / deepseek-v4-flash
- **形态**：1 个会话 20 轮固定任务序列（读/写/查小操作，同一文件反复触碰——前缀缓存友好的典型 coding 会话）
- **观测**：`assistant/message` 事件的 `usage`（session/types.ts:245，含 cacheReadTokens）
- **命中率定义**：`ΣcacheReadTokens / Σ(cacheReadTokens + inputTokens)`——分母 = prompt_tokens（llm-deepseek 的 `mapUsage` 已把 cacheRead 从 inputTokens 扣除，translate.ts:57，故分母取两者之和）
- **运行**：`node --env-file=.env --import tsx/esm examples/headless-agent/baseline-probe.mts <run> <out.json>`，连跑 3 次

## 结果总览

| run | 未命中输入 (inputTokens) | 缓存读取 (cacheReadTokens) | 总体命中率 |
|---|---|---|---|
| run1 | 5,237 | 147,584 | **0.9657** |
| run2 | 4,494 | 139,776 | **0.9689** |
| run3 | 4,282 | 139,776 | **0.9703** |

**三次平均：96.8%**（区间 96.6%-97.0%，稳定性好）

## 关键观察

1. **命中率随轮次单调上升**：turn 1 ≈ 95.2% → turn 20 ≈ 96.6-97.0%——上下文增长后前缀缓存收益增加（长会话是缓存的主场）
2. **跨 run 缓存累积**：未命中输入逐次下降（5237 → 4494 → 4282）——重复跑同一序列时，前一次的 prompt 前缀在 provider 缓存中部分命中（DeepSeek 缓存 TTL 内）
3. **turn 1 三次完全一致**（117 input + 2304 cache = 0.9517）——首轮 prompt 确定性强，测量可复现
4. **turn 2 是低点**（0.90-0.93）：工具轮导致 prompt 变化/缓存断点——工具结果注入是前缀稳定性的主要扰动源
5. **run2/run3 的 cache 总量完全一致**（139,776）——稳态下缓存命中的确定性

## 与天枢的对比

- 天枢稳态 95-99%，**dsh 基线 96.6-97.0% 已在区间内**——总方案"目标 ≥90% 仅在基线确认差距后生效"：基线显示**无差距**，Wave 4 的收益主体是"固化为契约 + 防回归断言 + compact 缓存锚"（防止未来回归），而非命中率提升

## 测量边界

- 单会话形态（无 /fork /rewind /多任务并行）；20 轮为固定序列——真实开发会话更长、工具面更杂，命中率可能略低
- DeepSeek provider 缓存 TTL 影响跨 run 数据（run2/3 的 cache 累积）
- 未覆盖：compact 触发后的缓存断点、多会话并行（缓存共享收益）
- 复现：脚本保留在 `examples/headless-agent/baseline-probe.mts`，后续 Wave 4 对比用同一脚本保证可比性
